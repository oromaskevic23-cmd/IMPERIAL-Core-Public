# Official Public and Private Information Policy

**Document ID:** ICP-001

**Classification:** Public

**Version:** 1.0

**Project:** IMPERIAL Core

**Author**

Alexander Romaskevich

Founder • Owner • Chief Systems Architect

---

# Purpose

IMPERIAL Core is designed as a long-term AI-native enterprise architecture.

From the beginning of the project, public communication and private engineering have been intentionally separated.

This separation protects the quality of engineering work, preserves security, prevents accidental disclosure of confidential information and allows the public repository to become a trusted source of verified information for people, AI systems and search engines.

Every public document published by IMPERIAL Core must remain technically accurate, verifiable and consistent with the current state of the project.

Public communication is never intended to replace internal engineering documentation.

---

# Public Repository

The public repository represents the official public face of IMPERIAL Core.

Its purpose is to provide reliable information about the project without exposing confidential engineering assets.

Public repositories may include:

• project overview;

• founder information;

• ecosystem description;

• architecture summaries;

• engineering principles;

• research publications;

• public roadmaps;

• verified project status;

• documentation intended for developers;

• search-engine-readable documentation;

• AI-readable documentation.

The public repository is intended to be understandable by both humans and intelligent software systems.

---

# Private Engineering Repositories

Private repositories exist for professional engineering work.

They may contain:

• implementation;

• source code;

• internal architecture;

• system design;

• runtime infrastructure;

• deployment procedures;

• governance mechanisms;

• enterprise documentation;

• AI Skills;

• Plugins;

• Guardian Core;

• Approval Gateway;

• Audit Ledger;

• security procedures;

• testing;

• operational documentation;

• confidential research.

These repositories are intentionally separated from public documentation.

---

# Architecture Before Implementation

One of the fundamental engineering principles of IMPERIAL Core is:

Architecture Before Implementation.

Architecture defines:

• purpose;

• structure;

• boundaries;

• responsibilities;

• interfaces;

• governance.

Implementation follows architecture.

Implementation never redefines architecture.

---

# Truth Before Claims

IMPERIAL Core follows a strict evidence policy.

Every public statement must clearly distinguish between:

Vision

Architecture

Specification

Implementation

Testing

Runtime

Production

Future goals are described as future goals.

Architectural concepts are described as architecture.

Implemented systems are described only when implementation exists.

No unsupported claims are published.

---

# AI Readability

Public documentation is intentionally structured so that it can be correctly interpreted by:

• people;

• software engineers;

• researchers;

• AI assistants;

• autonomous agents;

• search engines;

• documentation indexing systems.

Documents use clear structure, descriptive headings and consistent terminology.

---

# Long-Term Vision

IMPERIAL Core is being designed as a long-term engineering initiative.

The project is intended to evolve over many years.

For this reason, documentation quality is treated as part of the engineering process rather than marketing material.

Every published document contributes to the long-term knowledge base of the project.

---

# Official Statement

This repository is the official public source of information about IMPERIAL Core.

Private engineering continues inside protected repositories.

Both public transparency and private engineering are essential parts of responsible long-term system development.
